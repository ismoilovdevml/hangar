Concepts in one minute#

  • Repository: a named container of one format and one type. Names match ^[a-z0-9][a-z0-9-]{1,62}$.
  • Types:
    • hosted: clients publish into it.
    • proxy: fetches from a remote registry on demand and caches what it fetched.
    • group: an ordered list of repositories of the same format behind one URL. Reads try the members in order. Docker, npm, NuGet, PyPI, Go, Cargo, APT and RPM groups can forward writes to one hosted member (write_member). Maven and raw groups are read-only.
  • URLs: every format except Docker is served at <base_url>/repository/<repo>/.... Docker/OCI is served at <base_url>/v2/, and the first path segment of the image name selects the repository; a Docker repository can also get its own host name or port (a connector, see docker.md).
  • Credentials: every client authenticates with HTTP Basic (any username plus a personal access token as the password) or Authorization: Bearer <token>. Tokens start with hgr_.
  • server.base_url (HANGAR_SERVER_BASE_URL) must be the URL clients use. Every absolute link Hangar generates is built from it: npm tarball URLs, PyPI file links, the Docker token realm, NuGet resource URLs.

Things that apply to every proxy repository#

  • Proxy repositories cannot reach loopback, private, link-local or cloud metadata addresses by default. To proxy an internal server, list it in http.allow_private_networks (HANGAR_HTTP_ALLOW_PRIVATE_NETWORKS, comma-separated CIDRs, IPs, host names or .domain suffixes).

  • A corporate outbound proxy is configured once in http.proxy (HANGAR_HTTP_PROXY) and inherited by every proxy repository; see hangar.example.yaml.

  • Common proxy settings in config.proxy:

    Key Meaning
    remote_url upstream base URL (required)
    metadata_ttl, content_ttl, negative_cache_ttl cache lifetimes, Go durations such as 30m, 24h
    auth upstream credentials: {"kind": "basic", "username": "...", "password": "..."}, {"kind": "bearer", "token": "..."} or {"kind": "header", "header_name": "...", "token": "..."}
    related_hosts other hosts the remote links to (file CDNs, API hosts) that may be fetched on its behalf: host names, host:port or .domain suffixes; the remote's credentials are never sent there
    offline true: never contact the remote, serve only cached content (stale included), answer 404 for the rest
    max_concurrent_requests cap on requests in flight to the remote (0 = unlimited)
    http per-remote outbound settings: proxy, ca_bundle, timeouts, connection limits

  • Upstream credentials (auth, or a password inside remote_url) are encrypted with the server's secret key and never returned by the API. Set HANGAR_SECRET_KEY (openssl rand -base64 32, same value on every node) before adding them: without it, saving a repository that carries a credential answers 501. See docs/security.md.

  • When a remote answers 429, Hangar passes it on (with Retry-After) for content it has not cached and keeps serving what it has.

  • POST /api/v1/repositories/<name>/cache:invalidate makes a proxy forget remembered 404s and rate limits so the next request asks the remote again; cached content is kept.

  • Group members are merged. If a proxy member serves a public package with the same name as one of your internal packages, clients may resolve the public one (for example a higher version). Add routing rules: block internal names on the public proxy and reserve them for the hosted member.

Browsing#

Packages in the web UI is a tree of every repository you can read. Expand a repository to see what clients consume: folders (npm scopes, Maven groupId segments, image paths, module paths) lead down to packages, and a package opens to its versions, newest first. apt and rpm list their packages by name. A raw repository's files are its content, so its tree shows directories and files.

The files a repository stores (tarballs, manifests, Docker manifests and blobs, index documents) are on the repository's Files view, folder by folder in client paths:

Format Files
npm scope, package, then the package's files (tarballs, manifests)
Maven groupId segments, artifactId, version, files
NuGet package id, version, .nupkg / .nuspec
PyPI project, files
Go module path segments, module, @v, version, .info / .mod / .zip
Cargo crate, version, .crate
Docker image path, then manifests (tags and digests) and blobs
Helm chart, version, .tgz / .prov
raw directories and files

A group shows the merged content of the members you can read; each entry names the member that holds it. The tree is keyboard navigable (arrow keys, Home, End, Enter), loads folders on demand, and the selection is part of the URL, so a link opens the same node.

Selecting a package or version shows its README (rendered from the package's own files; links and images are restricted), licences, downloads, vulnerability status, its versions and files, the repositories that hold it, and the client commands to install it. Selecting a file shows its path, size, checksums, dates, and, in a proxy, that it is a cached copy. A Docker version's size and its Layers tab come from the image manifest (a multi-platform index is sized by its linux/amd64 image). Delete version, Delete package (every version, on the Versions tab) and Delete file need repo:<name>:delete; all are audited and release the files' blobs for compaction. Docker layers and manifests are shared by tags, so they are deleted with their version, never one file at a time.

The same data is in the REST API: GET /api/v1/repositories/<name>/browse?path=<folder> (direct children, cursor-paged; view=packages gives the tree, the default view=files the stored files), GET|DELETE /api/v1/assets/<id> and GET /api/v1/components/<id>/info (README, licences, keywords).

Plain HTTP#

Hangar's listener speaks plain HTTP; terminate TLS in a reverse proxy or load balancer and set server.base_url to the https:// URL. List the proxy in server.trusted_proxies so X-Forwarded-* headers are honoured (HSTS is then sent on HTTPS requests). Every guide notes the extra client flag needed when you test against an http:// URL.

See also: docs/FORMATS.md (protocol details per format) and api/openapi.yaml (full REST reference).
