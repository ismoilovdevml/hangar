Changelog

Unreleased#

v0.2.0 (2026-11-21)#

NATS is gone: events and jobs run on the PostgreSQL every node already shares. Also new: webhooks, CI OIDC trusted publishing, hangar apply, context-bound secrets, faster search, and signed releases with the Helm chart on OCI. Read the upgrade notes before upgrading; full steps are in upgrade.md.

Upgrade notes#

  • Upgrade every node together. v0.1 and v0.2 nodes share neither events nor jobs. With Helm, add --set updateStrategy.type=Recreate --set updateStrategy.rollingUpdate=null to this one upgrade to avoid a mixed window. Run the migrations (00310–00380).
  • NATS is no longer used. Remove nats: and HANGAR_NATS_* (they are ignored, with one startup warning). Jobs still queued in JetStream are not carried over: drain the queue first (hangar_job_queue_depth = 0) to lose none; scheduled jobs run again on their next schedule. Afterwards the NATS server and its data can be removed:
    • Helm: the chart no longer deploys NATS; the upgrade deletes its StatefulSet, Services and Secret but keeps the PVCs (kubectl delete pvc -l app.kubernetes.io/instance=<release>,app.kubernetes.io/component=nats). Old nats.* values are accepted and ignored.
    • Compose: install.sh no longer creates or mounts <data>/nats and leaves an existing one in place for a rollback; remove it when you no longer need one.
  • PostgreSQL connections. Each node holds one extra long-lived session for the event listener: budget nodes × (database.max_conns + 17). PgBouncer must use session pooling, not transaction pooling.
  • System logs across nodes are read over HTTP: each node's server.node_url (HANGAR_SERVER_NODE_URL) must be reachable from the others. The chart sets it to the pod IP and its NetworkPolicy allows pod-to-pod HTTP; elsewhere it defaults to the local address used to reach the database plus the port of server.addr.
  • Secrets are re-sealed as hgs2 (bound to their row and field) on the first start. v0.1.x cannot read them afterwards: to roll back, restore the pre-upgrade backup, or stop every v0.2 node and run hangar admin rotate-secrets --downgrade before starting v0.1.x (which also needs its NATS back).
  • Search pages stop at 10,000 results. pg_trgm is created by the migration when the database owner may; otherwise Hangar warns at start and CREATE EXTENSION pg_trgm; SELECT hangar_search_trgm(); adds the index later.
  • Retention. New tasks.run_retention (default 2160h, 90 days) prunes finished task runs; the first run after the upgrade deletes older ones (set 0s to keep all). New audit.retention defaults to 0s: audit history is kept unless you set a limit.
  • Dropped schema: the unused nodes, replication_targets and replication_state tables and task_runs.node_id.
  • Metrics renamed: hangar_nats_connected → hangar_event_listener_connected, hangar_nats_reconnects_total → hangar_event_listener_reconnects_total; new hangar_job_queue_dead.
  • Web UI addresses: /cluster, /settings/system, /settings and /access?tab=audit redirect to the new System area, Audit log and settings pages.
  • APT and RPM groups with proxy members need the remote's public keys in the proxy's format.remote_keys; without them the group answers 400.

Events and jobs on PostgreSQL#

  • Cache invalidation and live events use LISTEN/NOTIFY on one dedicated connection per node; after a reconnect every cache resyncs and live streams restart.
  • Jobs (task runs, scans, policy jobs) are claimed from a jobs table with FOR UPDATE SKIP LOCKED under a lease that long jobs renew; expired leases are reclaimed, failed jobs are retried with backoff and kept as dead for 7 days. One job per type at a time per node, as in v0.1.9.
  • APT and RPM reindexing and npm state cleanup are durable, debounced jobs run once per repository: deleting 1,000 packages triggers one reindex, not one per node per package, and nothing is lost when a node restarts.
  • System logs of other nodes are fetched over signed HTTP.
  • /readyz "eventbus" reports the listener; System status shows it with job counts.

New features#

  • Webhooks (Settings › Webhooks, /api/v1/webhooks): component published, deleted, quarantined and released, repository created and deleted, and new scan findings, sent as generic JSON, Slack or Microsoft Teams messages. Deliveries are signed (X-Hangar-Signature, HMAC-SHA256), retried with backoff for about an hour from a PostgreSQL outbox, can be inspected and redelivered, and a webhook that keeps failing is disabled. URLs follow the outbound address policy of proxy remotes and are write-only; a URL on another host needs the secret again. New privilege system:webhooks:read|admin. See webhooks.
  • CI OIDC trusted publishing (Settings › CI trust, POST /api/v1/auth/oidc/exchange): GitHub Actions, GitLab CI and other OIDC issuers trade their ID token for a short-lived token scoped by a trust policy (issuer, audience, claim conditions, service account, scopes, lifetime up to 1 h). Tokens are single-use per ID token, never listed or rotated, and revoked when their policy changes. GitHub and GitLab policies must pin the owner. Managing policies needs system:settings:admin and every privilege the policy grants. See CI OIDC.
  • Configuration as code: hangar apply -f FILE|DIR, hangar diff and hangar export manage repositories (every format and type, with routing rules), blob stores, cleanup policies, roles and outbound proxies from YAML over the REST API. Plans are idempotent and ordered by dependency; secrets come from valueFrom: {env|file} and are never exported; --prune deletes only what the named apply set created or adopted (kept in the new /resource-labels API). JSON schema: api/hangar-config.schema.json. See config as code.
  • APT and RPM groups take proxy members. A remote's packages are listed next to hosted ones under the group's signature after the remote's own signature (InRelease/Release.gpg, repomd.xml.asc) is verified with format.remote_keys; quarantine, routing rules and offline members are respected. The web UI has a "Remote signing keys" field.

Security#

  • Secrets bound to their place (hgs2): a sealed value copied to another row or field can no longer be opened there, closing the replay path that v0.1.9 blocked at the API. Key rotation and the startup sweep upgrade hgs1 values; see ADR 0010.
  • Login and failed-authentication rate limits are cluster-wide (new rate_limit_buckets table), not per node.
  • Repository imports from APT, RPM, Cargo and PyPI sources bound decompression and memory; an oversized index fails the import instead of being read truncated.
  • PyPI proxies hide quarantined cached files past the first 1,000 versions.

Performance and reliability#

  • Search runs one statement over one match set with a trigram index for substrings: in a 100k-component test, an empty query went from 356 to 127 ms and a query with no match from 17 to 0.6 ms.
  • Blob GC lists candidates from two partial indexes (a batch went from 23–33 ms to under 1 ms).
  • Audit partitions: rows that landed in the default partition no longer block creating later months; months older than audit.retention are dropped when it is set.
  • S3: small reads and writes take one request instead of HEAD plus request; publishing no longer calls storage inside its database transaction, and a blob GC run racing a publish no longer fails it.
  • Outbound HTTP no longer takes a global lock per request; the client cache is bounded.
  • System status shows OIDC and LDAP enabled from the web UI.

Web UI#

  • One System area (/system: Status, Nodes, Logs, About) replaces Cluster, System status, System logs and Settings › System; users without cluster access land on About instead of an error. One Audit log (/audit); the Access page drops its Audit tab. The Settings hub is gone.
  • Dusk (dark) theme is readable: every colour comes from tokens checked for WCAG AA in both themes.
  • An empty server's Overview starts with "Create your first repository".
  • Admins of some repositories (e.g. repo:npm-*:admin) can create repositories on the default blob store.
  • Vulnerabilities: lighter row actions; the quarantined count is no longer cut off. Search: one search box, examples from your own repositories. New task: errors at each field. Most downloaded keeps npm scopes and Maven groups. Large package trees no longer recompute on every scroll.
  • One dialog, confirmation, filter field, error message and permission check everywhere; the permission check now matches the server exactly.
  • Unhashed static files (login wallpaper, favicon) are revalidated with an ETag.
  • The demo's numbers agree across pages.

Releases, deployment and docs#

  • Signed releases: both images (every platform), the Helm chart and every release file are signed with cosign (keyless, bound to the release workflow); SPDX SBOMs and SLSA provenance are attached. See verify a release.
  • Helm chart on OCI: helm install hangar oci://ghcr.io/ismoilovdevml/charts/hangar --version 0.2.0. Pod templates no longer repeat their selector labels (strict parsers such as kubeconform rejected them).
  • The release gate also runs govulncheck, npm audit, Trivy on both images and kubeconform on the chart; Dependabot proposes weekly grouped updates.
  • Every exported metric is documented (a test enforces it); the proxy upstream metrics and hangar_routing_blocked_total are on the dashboards.
  • Docs: getting started lists all 11 formats and the real write policy default; README compares Hangar with Nexus, Artifactory and Harbor; a code of conduct, issue forms and a pull request template were added.

v0.1.9 (2026-11-20)#

A security and reliability release. Upgrading is recommended for every installation; read Upgrade notes first.

Upgrade notes#

  • Repository-level proxies are checked like remote URLs. A repository whose config.proxy.http.proxy points at a private, loopback or link-local address is refused on save and blocked when dialled. List the address in http.allow_private_networks, or define it as a named proxy (Settings › Proxies) and use proxy_name. Until then any other update of such a repository is refused too.
  • S3 blob stores managed through the API need static keys. Creating, changing or testing an S3 store through the API without an access key is refused unless the new storage.allow_ambient_credentials is true (HANGAR_STORAGE_ALLOW_AMBIENT_CREDENTIALS). The default store from the configuration file and existing keyless stores keep working.
  • Sealed values are not accepted as input. API, YAML and UI inputs refuse hgs1.… secrets (400); omit the field to keep the stored secret.
  • Moving a secret's target needs the secret again. Changing an OIDC issuer origin, an LDAP URL, a proxy's scheme, host or port, or an S3 endpoint (also in :test) requires client_secret, bind_password, password or s3.secret_access_key to be entered again.
  • Compose installs: secrets/ is mounted read-only and the one-time admin password moves to <data>/bootstrap/initial-admin-password. install.sh creates bootstrap/ and moves an existing password; upgrade with install.sh rather than copying compose.yaml by hand.
  • Helm: the chart is 0.1.9 and defaults to the 0.1.9 images (it pointed at 0.1.0, and imageScanning.enabled pulled a scanner tag that does not exist). config.auth.oidc.client_secret and config.auth.ldap.bind_password in values now fail the render; pass them with extraEnv from a Secret.
  • npm login tokens are scoped to the repository (and a group's write member) and no longer reach other repositories or the REST API.
  • Unknown blob store names are an error: a repository whose named blob store is missing no longer writes to the default store.
  • The development compose project is now hangar-dev, so its old volumes (hangar_postgres, …) are no longer used.

Security#

  • SSRF through a repository proxy (critical): a repository's own http.proxy was added to the server-wide list of trusted proxy addresses, which skipped the outbound address guard for that address for every repository; a repository admin could reach cloud metadata or internal services. Only operator proxies are trusted now, and repository proxies pass the same policy as remote URLs.
  • Sealed secrets could be opened by replay (critical): a sealed hgs1. value copied from the database or a backup could be pasted into a repository or import task credential, and Hangar sent its plaintext to the configured host. Sealed input is refused everywhere a secret is accepted.
  • Stored secrets follow their endpoint: OIDC, LDAP, proxy and blob store saves and connection tests no longer send a stored secret to a changed host.
  • Probe and S3 dials refuse cloud metadata addresses; API-managed S3 stores no longer sign requests with the host's ambient AWS credentials.
  • Image imports send registry credentials only to the source's own origin or an https token service.
  • Sign-in providers cannot grant more than their editor holds: saving an enabled OIDC or LDAP provider needs every privilege of its default and mapped roles (a settings admin could map new users to Admin).
  • Tokens minted through a token stay inside its limits: a token created or rotated with an API or session token can't outlive it and inherits its allowed networks; rotating a token through itself no longer extends its life. Creating tokens in the web UI is unchanged.
  • Unlocking a user needs the same coverage as resetting their password.
  • GET /users/{self}/permissions with a scoped token shows only what the token can do.
  • npm login counts against auth.login_rate (429 with Retry-After) and refuses users who can't read the repository.
  • Opening a Docker connector port (connector.http_port) needs system:repos:admin.
  • Forwarded headers: behind trusted proxies, X-Forwarded-Proto and X-Forwarded-Host come from the outermost trusted proxy's entry, not the client's.
  • IPv6 clients are grouped by /64 for sign-in lockout and the login rate limit.
  • Event streams (/api/v1/events) close within about 30 s of sign-out, session or token expiry or revocation, or the account being disabled; role changes apply to open streams.
  • NuGet proxy cache poisoning: a proxied .nupkg whose manifest names a different id or version than the one requested is no longer cached under the manifest's identity (the client gets 502). Invalid ids in flat container and registration paths return 404.
  • Upstream URLs with dot segments (./.., also percent-encoded) taken from an index or a redirect are refused for every format, so they can't climb out of the remote's path with its credentials.
  • Archive bombs: uploads are refused with 400 when the archive expands past a cap (Helm chart over 256 MiB, .deb control member over 256 MiB, .crate over 1 GiB); package info stops reading after 1 GiB.
  • RPM: header lengths are no longer trusted for allocation (a 112-byte request could reserve 512 MiB); headers with more than 65,535 index entries are refused. Group metadata is kept only for roots that hold packages, so arbitrary paths no longer grow memory.
  • Quarantine fails closed: if the quarantine lookup fails, downloads answer 500 instead of serving the file (Maven, PyPI, NuGet, Go, Cargo, Helm). Quarantined Maven non-unique SNAPSHOTs return 403. npm proxy and group packuments hide quarantined versions, and latest moves to the highest remaining one.
  • Offline write members: group uploads to an offline write member return 503 (PyPI, Go, Cargo, APT, RPM).
  • Delete-only users can delete APT and RPM packages and unlist NuGet packages; the indexes are regenerated instead of failing with 403.
  • NuGet symbol packages are no longer accepted (they were stored but never served): the service index has no SymbolPackagePublish, and a symbol push returns 400.

Reliability#

  • Stopping the server no longer hangs while a web UI tab is open: event streams end when shutdown begins, instead of holding it for server.shutdown_timeout.
  • Docker connector ports drain and stop together with the main port; stopping takes at most drain_delay + shutdown_timeout.
  • Deadlock fixed (PostgreSQL 40P01) between download statistics and component deletes or publishes. While the database is unreachable, download counts for at most 10,000 assets are kept in memory; the rest are dropped with a warning.
  • Background jobs in HA: each node takes one job of a type at a time, so idle nodes pick up the backlog. Image scans longer than 10 minutes finish instead of being retried and dropped (the per-job limit is max(10m, 2×(scanner.timeout+1m)), 32 minutes by default). On shutdown, running jobs are cancelled and returned to the queue.
  • Idle transactions: database sessions idle inside a transaction for 5 minutes are ended, unless PostgreSQL or the database URL (idle_in_transaction_session_timeout) sets otherwise.
  • Blob GC deletes each blob in its own short transaction instead of holding a batch of row locks across storage calls; storage.gc.batch_size is now how many candidates are listed at a time.

Web UI#

  • Dialogs keep their own size and padding; the new-token dialog scrolls with Create and Cancel always visible, and only the chosen expiry is highlighted.
  • Search: Enter runs the search; a suggestion is inserted only when picked with the arrow keys or the mouse.
  • ⌘K no longer opens behind an open dialog; the Cleanup notice's Dismiss button is reachable with a screen reader.
  • Optional sections (token restrictions, upstream connection, sign-in setup) no longer close while you edit them.
  • Fewer background requests: status and upstream health refresh once a minute and pause in hidden tabs; the sign-in page no longer re-renders every second.
  • Package lists, search and findings refresh when packages are published, quarantined or deleted.
  • The Overview shows the system status once, server messages show local times, counts have thousands separators ("76,992 versions"), and long package names wrap at dots and slashes.
  • Placeholders for unbuilt features are gone (Dependents tab, Move repositories, Replication); the Cluster page is named Cluster.
  • The demo shows the real release version and a clean sample README.

Deployment, CI and observability#

  • Releases run the full test suite by default (set the repository variable RELEASE_SKIP_TESTS=true to skip), refuse a tag that doesn't match the chart's appVersion, and tag the scanner image only after its smoke test passes. Go tests under deploy/ now run with the rest.
  • Helm: NetworkPolicies for Trivy and the scan adapter; helm test works with networkPolicy.ingressFrom; the migration Job gets extraEnv, extraEnvFrom, extraVolumes, extraVolumeMounts, podLabels, podAnnotations and an existing ServiceAccount.
  • Installer: a failed pre-upgrade backup is retried on the next run instead of being skipped; GITHUB_TOKEN is used for the version lookup, with a fallback when the API rate limit is hit.
  • Alerts and dashboards: HangarUpstreamCircuitOpen resolves once a remote is idle; HangarDown matches any job containing hangar; "Remotes not healthy" leaves out remotes not used yet; the RSS and error panels are fixed. make alerts-check runs the alert rule tests when promtool is installed.

  • Cleanup policies (/api/v1/cleanup-policies): delete versions by age, download recency, keep-newest per package, version include/exclude regexes, keep globs, pre-release/snapshot only and minimum size, for attached repositories and repositories naming the policy in config.cleanup_policies. Quarantined versions and versions with the legal_hold attribute are never deleted. A dry-run preview (JSON or full CSV) is required before saving (preview_token); preview and run share one selection. Runs delete through the component service (audited, component.deleted events) in checkpointed batches, on a cron schedule or with Run now, and can be stopped.
  • Tasks (/api/v1/tasks): built-in tasks (docker GC, blob compaction, auth purge, audit partitions) and the task of every cleanup policy, with editable cron schedules, Run now, Stop, run history, leveled run logs (/tasks/{id}/runs/{run_id}/log) and live task.progress / task.finished events. Runs execute on any node, survive node loss (taken over and resumed from their checkpoint) and are handed back on shutdown; only the scheduler leader starts scheduled runs.
  • Docker GC (#7): deletes untagged manifests, their referrers entries and unreferenced layer/config blobs older than 7 days (configurable, dry run available); blob compaction then frees the bytes.
  • Blob stores: PUT (soft quota, credentials; location only while empty) and DELETE (empty stores only) on /api/v1/blob-stores/{name}.
  • API (#16): GET /system/status returns base_url and registry_host; soft_quota_bytes is nullable; online / enabled inputs are optional.
  • Cleanup and task changes require system:cleanup:write / system:tasks:write; reads require :read.
  • Web UI · Cleanup policies: policy list and an editor written as sentences (age, last download, pre-release only, keep newest N, keep tags matching globs), repository chips, a schedule builder that shows the cron in plain words with the next run, a mandatory preview (count, bytes, sample, full CSV export) before saving, Run now and Delete with confirmation, and run history.
  • Web UI · Scheduled tasks: "Running now" banner with live progress (SSE task.progress), time-left estimate and Stop; task table with schedule, last and next run, type/status/name filters in the URL, and Run now (confirmation for tasks that delete data). Task page with paged run history and a run view with progress and a live log.
  • Web UI · Audit log: filters for actor, action, target, outcome and time range (presets or a custom UTC range) kept in the URL, expandable event details, cursor paging, and CSV / NDJSON export with the same filters.
  • Web UI · System: status, version and build, uptime, nodes, dependency health, base URL and registry host, and the effective configuration with secrets masked.
  • Run, stop, save and delete actions are hidden from users without the matching system:<area> privilege; screens say plainly when a server does not support an endpoint yet.
  • Observability: Prometheus metrics for package traffic per format and repository type (requests, latency, upload and download bytes), blob store operations per driver, store usage, quotas and filesystem free space, proxy remote fetches and circuit breaker state, database statements and pool, job queue depth and job outcomes, NATS connection, authentication failures and lockouts, the audit queue and readiness. Labels are bounded: route patterns, standard methods and capped value sets, never raw paths.
  • Tracing: OpenTelemetry traces over OTLP/HTTP (observability.tracing.{enabled,endpoint,sample_ratio,service_name}) with spans for HTTP requests, database statements, blob store operations, proxy fetches and jobs; incoming W3C traceparent headers are honoured.
  • Logs: every request log record carries request_id, trace_id, principal, repository and format; credentials are scrubbed from all log output; observability.access_log.sample_ratio samples the access log (server errors are always logged). The access log fields bytes became bytes_in and bytes_out.
  • Deploy: Grafana dashboards (overview, formats, storage, upstreams, jobs, auth) and Prometheus alert rules with unit tests in deploy/observability/; metric reference in docs/operations/monitoring.md and a runbook per alert in docs/operations/runbooks.md.
  • Fix: request metrics (and the Overview screen numbers) are recorded when metrics.enabled is false; only the /metrics endpoint is turned off.
  • Proxy related hosts: proxy repositories fetch resources their remote links to on other hosts through the same upstream engine (SSRF guard, per-host circuit breaker, request collapsing, negative cache, outbound proxy, metrics), never sending the remote's credentials there. PyPI file downloads (files.pythonhosted.org) and NuGet search/registration hosts named by the service index (azuresearch-*.nuget.org) use it; npm follows tarball CDNs listed in the new proxy.related_hosts.
  • Rate limits (429): a remote's Retry-After is honoured for retries within a 10s budget; beyond that clients get 429 with the remote's Retry-After instead of 502 (a cached copy is served when there is one), the host is held until the wait passes and 429s no longer trip the circuit breaker. A rate-limited remote reports slow on the upstream health page.
  • Upstream tuning per proxy repository: max_concurrent_requests, http.max_conns_per_host, http.max_idle_conns_per_host, http.disable_http2, and http.body_timeout (stall timeout between body reads; 60s default). HTTP/2 is negotiated with health pings; interrupted large downloads resume with Range/If-Range when the remote supports it.
  • Offline mode (proxy.offline): a proxy repository serves only its cache and answers 404 for anything not cached, without contacting the remote.
  • Cache purge: POST /api/v1/repositories/{name}/cache:invalidate forgets a proxy repository's remembered 404s and rate-limit holds on every node (audited).
  • Metrics: hangar_proxy_upstream_requests_total{repository,host,result}, hangar_proxy_upstream_request_duration_seconds, hangar_proxy_upstream_retries_total, hangar_proxy_upstream_resumes_total, hangar_proxy_upstream_inflight_requests.
  • Access management (see docs/guides/access.md):
    • Members and service accounts: search and filter by role, status (active, locked, disabled) and source; disable/enable, unlock, admin password reset, sign out everywhere, delete — with guards for your own account and the last administrator. Service accounts take a description.
    • Self-service: PUT /me/password (current password required, other sessions end), PUT /me/profile, GET/DELETE /me/sessions.
    • Personal access tokens: last use is recorded with the client address; administrators list everyone's tokens (GET /tokens?all=true with owner, owner kind, status and name filters); scopes are validated; the session payload carries the token policy and expiry warnings (auth.token_expiry_warning, default 14 days).
    • Roles: GET /roles/{name}, add/remove members (/roles/{name}/members), privilege validation.
    • Effective permissions report: GET /users/{id}/permissions lists, per repository and system area, the allowed actions and the role, privilege or anonymous read behind each.
    • Every change and every refused attempt is audited (user.disable, user.enable, session.revoke, session.revoke_all, role.bind, role.unbind, …).
    • Web UI: Access & audit (members, service accounts, access tokens, roles with a privilege editor, access audit log) and My account (profile, password, tokens, signed-in devices, own permissions), with a create-token dialog that builds scopes, offers expiry presets and shows the secret once.
    • Migration 00040: tokens.last_used_ip, users.description, token indexes.
  • Docker / OCI — push through a group fixed: a group with a Docker Hub proxy member answered 502 to the existence probe of a new tag (HEAD /v2/<group>/<image>/manifests/<tag>), because Docker Hub answers 401 for unknown repositories. Remote 401/403/404/400 NAME_INVALID now mean MANIFEST_UNKNOWN / BLOB_UNKNOWN, 429 is passed on as TOOMANYREQUESTS, and a group treats an unreachable remote as a miss.
  • Docker / OCI — proxy blob dedup is confirmed with the remote: a blob already in the shared store is linked into a proxy only after a HEAD confirms the remote serves it under that name (no more serving stored bytes by digest alone).
  • Docker / OCI — quarantine by digest: manifests pulled by digest, platform manifests of a quarantined index, blobs that belong only to quarantined images and cross-repository mounts are refused (403 DENIED).
  • Docker / OCI — connectors: connector.host (e.g. cr.example.com) and connector.http_port route a host name or a dedicated port to one docker repository, with image names without the repository prefix and tokens bound to that entry point. nginx and Caddy examples in internal/formats/docker/README.md.
  • Docker / OCI — upload sessions: session records live in the blob store temp area (new optional core.TempStore, implemented by the fs and S3 drivers) instead of leaking a blob per request; sessions resume on any node and across restarts; the hourly built-in task docker-upload-cleanup ends abandoned sessions and releases leftover chunks to blob compaction.
  • npm: unpublished versions leave a tombstone and cannot be published again (403), as on the public registry; set config.format.reuse_unpublished_versions: true to allow reuse. Unpublishing now also needs repo:<name>:write (it rewrites the package state).
  • npm: package state changes (publish, dist-tags, deprecate, unpublish) are serialised per package across all nodes with PostgreSQL advisory locks (a dedicated pool of up to 16 connections per node), so concurrent dist-tag updates on different nodes are no longer lost.
  • Performance: hosted npm packuments are rendered once per change (about 6x the throughput of the previous build; 100-version packument p95 from 99 ms to 4 ms); generated Maven metadata is cached with event invalidation (document and checksums always agree); repository lookups are cached; component and asset listings keep using their indexes under generic query plans. Results: docs/operations/performance.md.
  • NuGet: hosted search uses a PostgreSQL full-text index (migration 00070). Words now match as prefixes of tokens: json and newt find Newtonsoft.Json, a substring such as tonsoft no longer does.
  • Events: asset.published and asset.deleted for assets without a component (repository metadata, raw files).
  • Tools: cmd/hangar-seed fills a database with synthetic components and assets; k6 load scenarios in test/load.
  • Docs: user guides in docs/guides (getting started, one page per client, CI integration, REST API) and a shorter README.
  • Container image: the web UI is always embedded; a static hangar-healthcheck probe drives the HEALTHCHECK on the distroless, non-root image; builds are reproducible (build date from SOURCE_DATE_EPOCH, no VCS stamping, no build ids).
  • Production Docker Compose (deploy/compose): Hangar, tuned PostgreSQL 16, MinIO with a bucket-only user, and Caddy with automatic TLS for the UI host and a separate registry host; secrets from .env (HANGAR_SECRET_KEY and HANGAR_DOCKER_TOKEN_KEY required), healthchecks, resource limits, read-only containers, /metrics kept off the public host, and an override for Docker port connectors.
  • Helm chart (deploy/helm/hangar): stateless multi-replica Deployment with anti-affinity, PDB and optional HPA; migrations in a pre-install and pre-upgrade hook Job; optional bundled NATS JetStream cluster; Ingress presets for ingress-nginx and Traefik with a registry host, or Gateway API routes; existingSecret for every secret, with generated secret and token keys kept across upgrades; ServiceMonitor, NetworkPolicies, connector ports on the Service, values.schema.json and validation of unsupported combinations.
  • Operations: backup and restore scripts (deploy/scripts: PostgreSQL dump plus an add-only blob copy for filesystem, S3 and the compose MinIO), a hardened systemd unit (deploy/systemd/hangar.service), deployment guides in docs/deploy (requirements and sizing, compose, Helm, binary, TLS and reverse proxies, corporate proxy, first administrator, backup, upgrades, high availability, troubleshooting), and a hangar.example.yaml that covers every configuration key. make deploy-check validates the chart, the compose stack and the scripts.

M0 — Skeleton (2026-11-03)#

Foundation every later milestone builds on. No package format is functional yet.

  • Server: single hangar binary with serve, migrate and version subcommands; chi router; request ids and JSON logs (slog); Prometheus /metrics; /healthz (liveness) and /readyz (PostgreSQL, blob store, NATS); graceful shutdown that fails readiness first and drains in-flight requests.
  • Configuration: hangar.yaml plus HANGAR_* environment overrides, strict unknown-key checking and validation (hangar.example.yaml). Includes outbound HTTP proxy / CA / timeout settings for proxy repositories and trusted reverse proxies.
  • Core contracts (internal/core): domain types (repositories, components, assets, digests, principals, privileges, events, jobs, audit events) and interfaces (BlobStore, Format, Upstream, HTTPClientFactory, RepositoryService, ComponentService, Authenticator, TokenIssuer, AuthZ, EventBus, JobQueue, AuditLog, Deps), with in-memory fakes and a blob store conformance suite in internal/core/coretest.
  • Formats: registry and /repository/{repo}/ dispatcher; /v2/ root mount for OCI. Stub packages for docker, npm, maven and raw (answer 501).
  • Storage: filesystem blob store with streaming sha256, dedup and atomic commit.
  • Database: goose migrations for the full data model (blob stores, blobs, repositories, groups, components, assets, identity and access, cleanup policies, tasks, month-partitioned append-only audit log, nodes, replication, findings) with seeded built-in roles. Tested up/down against PostgreSQL.
  • Events: embedded NATS JetStream for single-node mode or an external cluster; event bus and durable job queue with retries.
  • Outbound HTTP: client factory honouring global/per-remote proxies (http, https, socks5), no_proxy, proxy environment variables, extra CAs, credential scoping and timeouts.
  • API: api/openapi.yaml (OpenAPI 3.1) covering repositories, blob stores, components, search, findings, cleanup policies, tasks, users, roles, tokens, audit, cluster, overview metrics, system status and the SSE event stream. Implemented so far: GET /api/v1/system/status, /system/version, /formats; other endpoints answer 501.
  • Web UI hook: web/dist is embedded with -tags webui; otherwise a fallback page is served.
  • Delivery: Makefile, multi-stage Dockerfile (distroless, non-root), deploy/docker-compose.yml (PostgreSQL 16, MinIO, NATS, Trivy, Hangar), CI (vet/test with PostgreSQL, golangci-lint, govulncheck, web checks, image build).
  • Decisions: ADRs 0001–0009 in docs/adr/.
