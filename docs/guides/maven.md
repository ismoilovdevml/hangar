# Maven and Gradle

Hangar serves the Maven 2 repository layout. Maven and Gradle resolve from it and
deploy to it (`mvn deploy`, Gradle `maven-publish`).

Placeholders:

- `hangar.example.com`: the host of `server.base_url`.
- `<user>`: your username or a service account name.
- `<token>`: a personal access token (`hgr_...`), used as the password.
- `$HANGAR_TOKEN`: the token in an environment variable.

Repository URL: `https://hangar.example.com/repository/<repo>/`.

## Repositories

A typical setup: a release repository, a snapshot repository, a Maven Central
proxy, and a group that combines them for resolution.

### Hosted

```bash
curl -X POST https://hangar.example.com/api/v1/repositories \
  -H "Authorization: Bearer $HANGAR_TOKEN" -H 'Content-Type: application/json' \
  -d '{
        "name": "maven-releases",
        "format": "maven",
        "type": "hosted",
        "blob_store": "default",
        "config": {
          "hosted": { "write_policy": "allow_once" },
          "format": { "version_policy": "release" }
        }
      }'

curl -X POST https://hangar.example.com/api/v1/repositories \
  -H "Authorization: Bearer $HANGAR_TOKEN" -H 'Content-Type: application/json' \
  -d '{
        "name": "maven-snapshots",
        "format": "maven",
        "type": "hosted",
        "blob_store": "default",
        "config": {
          "hosted": { "write_policy": "allow" },
          "format": { "version_policy": "snapshot" }
        }
      }'
```

`config.format`:

| Key | Values | Default |
|---|---|---|
| `version_policy` | `release`, `snapshot`, `mixed` | `mixed` |
| `layout_policy` | `strict` (only Maven-layout paths), `permissive` (also store other files) | `strict` |

A `release` repository rejects SNAPSHOT uploads (400) and answers 404 for SNAPSHOT
paths; a `snapshot` repository does the opposite. With `allow_once`, redeploying a
release fails with `409`; SNAPSHOT builds stay deployable. `maven-metadata.xml` and
checksum files are generated by Hangar.

### Proxy (Maven Central)

```bash
curl -X POST https://hangar.example.com/api/v1/repositories \
  -H "Authorization: Bearer $HANGAR_TOKEN" -H 'Content-Type: application/json' \
  -d '{
        "name": "maven-central",
        "format": "maven",
        "type": "proxy",
        "blob_store": "default",
        "config": {
          "proxy": { "remote_url": "https://repo1.maven.org/maven2/", "metadata_ttl": "1h" },
          "format": { "version_policy": "release" }
        }
      }'
```

Artifacts are verified against the remote checksum and cached; metadata is
revalidated after `metadata_ttl`.

### Group

```bash
curl -X POST https://hangar.example.com/api/v1/repositories \
  -H "Authorization: Bearer $HANGAR_TOKEN" -H 'Content-Type: application/json' \
  -d '{
        "name": "maven-public",
        "format": "maven",
        "type": "group",
        "config": { "group": { "members": ["maven-releases", "maven-snapshots", "maven-central"] } }
      }'
```

Maven groups are read-only: `write_member` is rejected. Deploy to the hosted
repositories directly; resolve through the group (`maven-metadata.xml` is merged
across members).

## Maven

Maven sends credentials only after a `401` challenge, which Hangar answers with
`WWW-Authenticate: Basic`. Credentials live in `~/.m2/settings.xml`, keyed by a
server `id`.

### `~/.m2/settings.xml`

```xml
<settings>
  <servers>
    <server>
      <id>hangar</id>
      <username><user></username>
      <password>${env.HANGAR_TOKEN}</password>
    </server>
  </servers>

  <!-- Resolve everything, including Maven Central, through the group. -->
  <mirrors>
    <mirror>
      <id>hangar</id>
      <mirrorOf>*</mirrorOf>
      <url>https://hangar.example.com/repository/maven-public/</url>
    </mirror>
  </mirrors>

  <!-- Needed only if you depend on SNAPSHOT versions: the mirrored "central"
       repository has snapshots disabled by default. -->
  <profiles>
    <profile>
      <id>hangar-snapshots</id>
      <repositories>
        <repository>
          <id>central</id><url>http://central</url>
          <releases><enabled>true</enabled></releases>
          <snapshots><enabled>true</enabled></snapshots>
        </repository>
      </repositories>
      <pluginRepositories>
        <pluginRepository>
          <id>central</id><url>http://central</url>
          <releases><enabled>true</enabled></releases>
          <snapshots><enabled>true</enabled></snapshots>
        </pluginRepository>
      </pluginRepositories>
    </profile>
  </profiles>
  <activeProfiles>
    <activeProfile>hangar-snapshots</activeProfile>
  </activeProfiles>
</settings>
```

The mirror `id` and the deployment repository ids below are all `hangar`, so one
`<server>` entry covers resolution and deployment.

### `pom.xml`: deploy

```xml
<distributionManagement>
  <repository>
    <id>hangar</id>
    <url>https://hangar.example.com/repository/maven-releases/</url>
  </repository>
  <snapshotRepository>
    <id>hangar</id>
    <url>https://hangar.example.com/repository/maven-snapshots/</url>
  </snapshotRepository>
</distributionManagement>
```

```bash
export HANGAR_TOKEN='<token>'
mvn -B deploy
mvn -B dependency:get -Dartifact=com.acme:greeter:1.0.0
```

Signatures (`.asc`) are stored with the artifact. Maven 3.8.1 and later block
plain-HTTP repositories other than `localhost`; serve Hangar over HTTPS for Maven.

## Gradle

Gradle needs `isAllowInsecureProtocol = true` (Kotlin) or
`allowInsecureProtocol = true` (Groovy) only for `http://` URLs; drop it with HTTPS.

### Credentials

Either `~/.gradle/gradle.properties` (outside the project, never committed):

```properties
hangarUsername=<user>
hangarPassword=<token>
```

or the environment, e.g. `ORG_GRADLE_PROJECT_hangarUsername` and
`ORG_GRADLE_PROJECT_hangarPassword` (Gradle maps these to the same properties), or
read your own variables with `System.getenv(...)`.

### Kotlin DSL (`build.gradle.kts`)

Resolve through the group:

```kotlin
repositories {
    maven {
        name = "hangar"
        url = uri("https://hangar.example.com/repository/maven-public/")
        credentials(PasswordCredentials::class)   // reads hangarUsername / hangarPassword
    }
}
```

Publish with `maven-publish`:

```kotlin
plugins {
    `java-library`
    `maven-publish`
}

group = "com.acme"
version = "1.0.0"

publishing {
    publications {
        create<MavenPublication>("maven") {
            from(components["java"])
        }
    }
    repositories {
        maven {
            name = "hangar"
            val releases = uri("https://hangar.example.com/repository/maven-releases/")
            val snapshots = uri("https://hangar.example.com/repository/maven-snapshots/")
            url = if (version.toString().endsWith("SNAPSHOT")) snapshots else releases
            credentials(PasswordCredentials::class)
        }
    }
}
```

```bash
gradle publish
```

`credentials(PasswordCredentials::class)` with `name = "hangar"` reads the Gradle
properties `hangarUsername` and `hangarPassword`.

### Groovy DSL (`build.gradle`)

```groovy
plugins {
    id 'java-library'
    id 'maven-publish'
}

group = 'com.acme'
version = '1.0.0'

repositories {
    maven {
        url = 'https://hangar.example.com/repository/maven-public/'
        credentials {
            username = System.getenv('HANGAR_USER')
            password = System.getenv('HANGAR_TOKEN')
        }
    }
}

publishing {
    publications {
        maven(MavenPublication) { from components.java }
    }
    repositories {
        maven {
            name = 'hangar'
            url = version.endsWith('SNAPSHOT')
                ? 'https://hangar.example.com/repository/maven-snapshots/'
                : 'https://hangar.example.com/repository/maven-releases/'
            credentials(PasswordCredentials)   // or credentials { username = ...; password = ... }
        }
    }
}
```

Gradle module metadata (`.module`) is stored and served like any other artifact
file.

## Browsing and deleting

- `GET https://hangar.example.com/repository/maven-releases/com/acme/` lists a
  directory (HTML; JSON with `Accept: application/json` or `?format=json`).
- `DELETE` on a file, a version directory or an artifact directory of a hosted
  repository removes it (needs `repo:<name>:delete`); metadata is regenerated.

```bash
curl -u <user>:'<token>' -X DELETE \
  https://hangar.example.com/repository/maven-releases/com/acme/greeter/1.0.0
```

## Routing rules

A group that combines a hosted repository with a public proxy can serve a
public package published under one of your internal names. Block internal
names on the proxy and reserve them for the hosted member (for example `com.edcom`);
see [routing-rules.md](routing-rules.md).
